# Практика №4. Минимальная дизайн-система Стоп-Спам

## Исходное состояние

Ветка `main` была чистой на коммите `8ac1e5134feb3df9f303da1e7340e1309559e6e5`. Изучены бриф, четыре HTML-страницы сайта, два CSS-файла, сценарий на JavaScript и четыре скриншота практики №3. Визуальной основой служат Inter, синий акцент, белый фон, поле проверки и карточки результата с зелёным или красным вердиктом. Папка практики №4 была пуста.

В CSS повторялись оттенки поверхностей, границ, текста и теней. Для похожих отступов встречались, например, 8, 9 и 10 px, а также 48 и 50 px. На сайте были два уровня риска. Одно совпадение сразу давало высокий риск. Для пустого отчёта не было отдельного состояния, а ошибка анализа показывала короткий статус без подробностей и без доступа к сохранённому сообщению.

## Что реализовано

- [Токены](tokens.css) для палитры, шкалы отступов, скруглений, типографики, теней и фокуса. Сайт импортирует этот файл из общей таблицы стилей.
- [Семь компонентов](preview.html?view=components) с общими правилами и вариантами. Кнопка, поле ввода, карточка результата, риск, уведомление, карточка признака и индикатор загрузки.
- Обновлённая [форма проверки](../../site/index.html) с подсказкой о поддерживаемых источниках, счётчиком, исходными примерами и встроенной ошибкой ввода.
- [Четыре состояния результата](preview.html?view=empty). Пустой отчёт ведёт к полю формы. Загрузка показывает прогресс и блокирует повторный запуск. Сбой объясняет причину и позволяет посмотреть сохранённый текст и повторить запрос. Отчёт показывает проверенный текст, вердикт, риск, объяснение, признаки, рекомендации и действие для новой проверки.
- Сохранились существующие страницы и URL, примеры ввода, отмена, переключатель учебного сбоя, диалоги и повторная проверка. Проверка выполняется локально в браузере на исходных текстовых правилах.

**До обновления** подсчитаны литералы из `site/styles.css` и `site/report.css` исходного коммита. **После обновления** подсчитаны те же файлы, токены и CSS компонентов и витрины. Расчёт воспроизводится командой `node design/practice-4/count-tokens.mjs` из корня репозитория.

- Цвета HEX и RGB(A) приведены к единому формату. Литеральные альфа-варианты исходного CSS учитываются. Производные тени, прозрачность и фильтры, вычисленные из токенов, не образуют новых исходных цветов. Цвета внутри PNG и SVG исключены.
- В отступы включены ненулевые значения `margin`, `padding`, `gap`, `scroll-margin-top` и токены шкалы. Размеры элементов, межстрочные интервалы, рамки, радиусы и смещения теней исключены.

## Стресс-тест

Тесты выполнены в Chrome на 390 и 1440 CSS px. Проверялись ширина документа, границы видимых карточек и текстовых блоков, доступность изображений, сохранность переданного текста и соответствие результата выбранному сценарию. Демонстрационные проценты и длинные данные отчёта можно переключать на [витрине стресс-теста](preview.html?view=stress).

| Случай | Проверенный результат на обеих ширинах |
|---|---|
| Пустой ввод | Проверка не стартует. Видна ошибка, фокус переводится на поле. |
| Очень короткий ввод | «Да» даёт средний риск и объяснение, что данных мало. |
| Очень длинный ввод | 4000 символов без пробелов дошли до отчёта полностью и перенеслись внутри карточки. Для программно переданных 4001 символов сработала валидация. |
| Много ссылок | 24 длинные ссылки отобразились как текст, перенеслись по ширине и не растянули карточку. |
| Эмодзи и необычные символы | Последовательности 👍🏽, 👩‍💻, Ⅻ и Ａ дошли до отчёта без изменений. |
| Длинное имя отправителя | Строка без пробелов перенеслась в карточке сообщения на демонстрационной странице. |
| Длинное объяснение | 16 абзацных фрагментов расширили отчёт по высоте. Рекомендация осталась после объяснения. |
| Низкая уверенность 51% | Число помечено как демонстрационное. Показан средний риск. |
| Высокая уверенность 98% | Число помечено как демонстрационное. Карточка и текстовый бейдж показывают высокий риск. |
| Неоднозначный ответ | Показаны текст «Однозначный вердикт недоступен» и рекомендация проверить отправителя. |

Отдельно проверены открытие отчётов высокого и низкого риска, отмена с возвратом текста, блокировка повторного запуска, сбой с сохранением текста, повтор после сбоя и открытие диалога обратной связи. На итоговом прогоне горизонтального переполнения не обнаружено. Для длинных входных данных применены перенос целых строк по доступной ширине, `min-width: 0` у элементов сетки и гибкая высота карточек.

Проверен расчёт контраста основных пар. Тёмный текст на белом — 17,10:1, подписи на светло-синем — 5,85:1, белый текст на основном акценте — 7,51:1. Бейджи низкого, среднего и высокого риска — 4,79:1, 6,15:1 и 8,62:1 соответственно. Для элементов управления предусмотрен `:focus-visible`, для сообщения в состоянии ошибки проверен перевод фокуса.

## Границы реализации

Обученной модели и сервера в репозитории нет. При вводе произвольного сообщения проверка остаётся эвристической, а в поле уверенности показано «Уверенность модели недоступна». Демонстрационные 51%, 92% и 98% иллюстрируют работу интерфейса. Диалог обратной связи сохраняет прежнее поведение сайта. Для отправки отзывов потребуется сервер.

Скриншоты сняты с локальной рабочей версии через HTTP по пути репозитория. Развёртывание текущих изменений на GitHub Pages не выполнялось. Бриф и материалы предыдущей практики сохранены.
