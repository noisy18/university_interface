# СТОПСПАМ · Хэндофф

СТОПСПАМ проверяет текст из мессенджеров, SMS, почты и социальных сетей и помогает оценить признаки мошенничества. Приоритетная аудитория — студенты, которым могут писать от имени деканата, работодателя или другой знакомой организации.

## Как запустить

Из корня репозитория запустите HTTP-сервер. Для действующего сайта требуется только Python 3 и браузер.

```powershell
python -m http.server 8000 --bind 127.0.0.1
```

Откройте [действующую локальную версию](http://127.0.0.1:8000/site/). Точка входа — `site/index.html`. Запуск по HTTP сохраняет работу переходов и временного хранилища между страницами.

Для пакета передачи установите Jinja2 и соберите страницы отдельной командой. Команды выполняются из корня репозитория. Сервер можно оставить запущенным в соседнем терминале.

```powershell
python -m pip install -r handoff/requirements.txt
python handoff/render_preview.py
```

- [Форма проверки](http://127.0.0.1:8000/handoff/preview/)
- [Учебный отчёт](http://127.0.0.1:8000/handoff/preview/result.html)
- [Все состояния](http://127.0.0.1:8000/handoff/preview/states.html)

В форме можно ввести сообщение или выбрать один из примеров. Флажок «Имитировать сбой следующей проверки» однократно включает ошибку, после которой доступен повтор с тем же текстом. Превью собирается из шаблонов локально, работает без серверного API и не отправляет текст по сети.

## Страницы

- **`pages/upload.html`** — заголовок, описание, форма, подсказка, оригинальные примеры и краткое объяснение сценария. Результат появляется в `#analysis-output` без перезагрузки.
- **`pages/result.html`** — отдельная страница отчёта. Она использует тот же фрагмент результата, что и форма.
- **`pages/states.html`** — витрина состояний подряд, включая учебный отчёт с низкой уверенностью.

## Предварительный контракт данных

Это проект структуры для будущего сервера. Шаблон получает нормализованный объект `result`.

| Поле               | Тип              | Обязательность | Значение и обработка                                                                                                                                                              |
| ------------------ | ---------------- | -------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `message`          | string           | Да             | Исходный текст, от 1 до 4000 кодовых единиц UTF-16 после удаления внешних пробелов. Сохраняйте перевод строк.                                                                     |
| `verdict`          | string           | Да             | `spam`, `phishing`, `suspicious`, `likely_safe`. Интерфейс использует русские подписи из `verdict_labels`.                                                                        |
| `risk_level`       | string           | Да             | `low`, `medium`, `high`. Интерфейс использует `risk_labels`.                                                                                                                      |
| `confidence`       | float или null   | Нет            | Конечное число от 0 до 1 включительно. При отсутствии или некорректном значении адаптер передаёт `null`. Интерфейс показывает, что уверенность недоступна.                        |
| `detected_signals` | array            | Нет            | Элементы `{title: string, description: string, detected: boolean}`. При отсутствии передайте пустой массив. `false` означает, что конкретный признак был проверен и не обнаружен. |
| `explanation`      | string           | Да             | Краткое объяснение результата обычным текстом.                                                                                                                                    |
| `recommendations`  | array of strings | Да             | Хотя бы одно понятное действие.                                                                                                                                                   |

Адаптер проверяет типы, перечисления и обязательные поля до рендера. Он удаляет некорректные элементы необязательного списка. При отсутствии ответа модели, неизвестном риске, вердикте или другом обязательном поле рендерится `state-error.html`. Исходный ввод сохраняется для повтора. Проектируемое правило низкой уверенности — `confidence < 0.60`, если число известно. Адаптер передаёт вычисленный флаг `low_confidence`. Условие показывается на учебном примере 51%, сам порог потребуется согласовать по данным модели. Флаг `is_demo` задаёт приложение для учебных примеров. Эти два флага относятся к представлению.

## Дальнейшее развитие

1. Подключить Jinja2 к FastAPI и передавать в шаблоны URL формы и статики, подписи и нормализованный результат. Для `base.html` используйте `static_url`, `upload_url`, `analyze_url` и `htmx_url`. Для формы передавайте `examples` и `demo=false`. Для отчёта нужны `risk_labels` и `verdict_labels`.
2. При наличии `analyze_url` форма получает `hx-post`, `hx-target="#analysis-output"`, `hx-swap="innerHTML"`, блокировку кнопки и политику одного запроса. Подключите проверенный файл HTMX через `htmx_url`. Название и путь реального маршрута определяются при интеграции. [Документация HTMX](https://htmx.org/docs/)
3. Для HTMX-ответа рендерить `state-result.html` или `state-error.html`, возвращая только содержимое цели. Для ожидаемой ошибки с готовым HTML использовать ответ, допускающий подмену фрагмента, например `200`. При сетевом сбое клиент покажет встроенную ошибку и сохранит ввод. При рендере фрагмента ошибки передайте `interactive=true`, `message`, `error_message` и `upload_url`. Обычный POST без HTMX должен возвращать страницу результата или форму с ошибкой. [События HTMX](https://htmx.org/events/)
4. Подключить реальную модель и слой валидации. Избегать логирования исходных сообщений. Проверить защиту запроса, ошибки связи, время ожидания и условия показа низкой уверенности. Оставить экранирование HTML включённым. [Документация Jinja](https://jinja.palletsprojects.com/en/stable/api/#autoescaping)

## Ограничения

Обученная ML-модель и FastAPI в репозитории отсутствуют. HTMX подготовлен на уровне шаблонов и обработчиков, а серверная интеграция пока не проверена. Статический сценарий оценивает текстовые признаки в браузере. При произвольном вводе он показывает, что уверенность модели недоступна. Учебные 51% и 98% подписаны как примеры. Контракт предварительный. Реальные вердикты и оценку уверенности в дальнейшем должен передавать сервер. Проверка текста не гарантирует абсолютного определения мошенничества.

Результаты сверки, клавиатурной и браузерной проверки находятся в [qa.md](qa.md).
