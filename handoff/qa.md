## Б. Клавиатура и семантика

В Chrome отправлены настоящие клавиатурные события через DevTools Protocol. Проверки выполнены на 390 и 1440 px. Это проверка поведения клавиатуры в браузере, отдельная сессия со скринридером не проводилась.

| Проверка      | Результат                                                                                                                                                                                                    |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Tab и порядок | Логотип → «Как это работает» → «О проекте» → профиль → поле → отправка. Фокус поля виден по синей границе карточки                                                                                           |
| Enter         | Встроенная проверка пустого поля переводит фокус на поле. Заполненная форма начинает анализ. Enter раскрывает сохранённый текст при ошибке                                                                   |
| Space         | Открывает диалог «О проекте» с кнопки                                                                                                                                                                        |
| Escape        | Закрывает диалог и возвращает фокус кнопке, которая его открыла                                                                                                                                              |
| Семантика     | У textarea один связанный `label`. Действия выполняют кнопки, переходы — ссылки. У логотипа содержательный `alt`, у декоративных иконок пустой. Проверены загрузка изображений и отсутствие повторяющихся ID |
| Фрагменты     | При загрузке повторный запуск блокируется. После результата или ошибки фокус переводится в область результатов. После отмены возвращается к текущему вводу                                                   |

Найденная проблема доступности: первоначально имя результата задавалось через `aria-label` на безымянном `div`. Lighthouse отметил `aria-prohibited-attr`. Контейнер заменён на именованную `section`, которая образует область с доступным именем. Ограничений управления, требующих мыши, в проверенном пути не обнаружено.

## В. Lighthouse

**Lighthouse 13.6.0, Chrome, категория Accessibility, локальная сборка по HTTP.** Desktop запущен с `--preset=desktop`, Mobile — с обычным мобильным профилем. Проверены отдельная страница результата и галерея, где видны все состояния.

| Проверка Accessibility | Desktop |  Mobile |
| ---------------------- | ------: | ------: |
| Форма проверки         | 100/100 | 100/100 |
| Отдельный отчёт        | 100/100 | 100/100 |
| Галерея состояний      | 100/100 | 100/100 |

До исправления ARIA форма получила **96/100** на Desktop. В итоговых отчётах проверок с нулевой оценкой по категории Accessibility не осталось. Балл относится к автоматическим проверкам и дополняется клавиатурной проверкой выше.

Для повторения после сборки и запуска из [README](README.md) откройте нужную страницу в Chrome. В DevTools выберите **Lighthouse → Accessibility**, по очереди запустите режимы Desktop и Mobile. [Руководство Chrome DevTools](https://developer.chrome.com/docs/devtools/accessibility/reference)

Jinja2 отдельно отрендерил все сочетания четырёх вердиктов и трёх уровней риска, варианты с отсутствующей уверенностью и признаками, экранирование HTML в сообщении и атрибуты формы в режиме будущей интеграции.
